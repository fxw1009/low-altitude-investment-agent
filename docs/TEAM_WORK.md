# 团队并行分工

## 成员与主责

| 成员 | 角色 | 可立即并行完成的工作 | 阶段性交付 |
|---|---|---|---|
| 吕洪宇（队长） | 架构、Agent 编排、集成与答辩 | 建立仓库、接口协议、主后端骨架、模拟全流程 | 可运行 MVP、架构图、运行手册、答辩材料 |
| 武桐宇 | 产业链知识图谱 | 构建低空产业节点、公司/产品映射、事件传导规则 | `graph/nodes.csv`、`relations.csv`、`event_rules.json` |
| 刘芯妤 | Wind 数据与量化 | 制定字段、导出清洗数据、财务健康度与影响评分 | `financials.csv`、评分模块、数据口径文档 |
| 孙奇衍 | 政策事件与证据 RAG | 建立事件分类、收集政策/公告、制作证据库和测试集 | `events.csv`、`evidence.csv`、30 个测试案例 |
| 范笑薇 | 前端与可视化 | 基于 mock JSON 开发页面、产业链动态图、研报展示 | 图谱页面、排名页面、报告页面、Demo 素材 |

## 统一工作流

```text
事件 Agent ──────┐
图谱 Agent ──────┼──→ 总控 Agent ─→ 投研报告与过程追溯
财务 Agent ──────┤
证据 Agent ──────┘
```

四类分析可并行运行，不以单人完成为前置条件。总控 Agent 仅接收统一 JSON，不直接依赖内部实现。

## 第一周并行任务

| 成员 | 第 1 天 | 第 2–3 天 | 第 4–7 天 |
|---|---|---|---|
| 吕洪宇 | 初始化骨架与统一接口 | 总控 Agent、mock 数据链路 | 接入各模块首版数据并跑通 MVP |
| 武桐宇 | 定义产业链节点类型 | 录入公司—产品—环节映射 | 编写六类事件传导规则 |
| 刘芯妤 | 确定 Wind 字段及样本公司 | 导出、清洗近三年数据 | 输出首版财务与影响评分 |
| 孙奇衍 | 建立事件与证据字段 | 收集政策、公告、新闻 | 完成首批 10 个可复核案例 |
| 范笑薇 | 设计交互原型与视觉规范 | 基于 mock 数据开发界面 | 接入图谱、排名和报告视图 |

## 接口约定

```json
{
  "event": {
    "event_id": "EVT_001",
    "name": "动力电池价格下降15%",
    "type": "原材料价格变化",
    "direction": "下降"
  },
  "chain_path": ["动力电池", "电推进系统", "eVTOL整机", "低空运营"],
  "companies": [{
    "code": "000001.SZ",
    "name": "示例公司",
    "industry_role": "eVTOL整机",
    "impact_direction": "positive",
    "impact_score": 78,
    "financial_score": 72,
    "evidence_ids": ["EVD_001"]
  }]
}
```

## 周期性验收

- 每日 15 分钟站会：昨天交付、今日计划、接口阻碍；
- 每两天合并一次可运行小版本；
- 每周抽取一个标准事件做端到端演示；
- 所有结论必须有“原始来源 + 图谱路径/规则 + 计算结果”。
