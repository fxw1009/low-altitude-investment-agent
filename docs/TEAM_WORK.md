## 每个人的细化分工与独立交付

> [!IMPORTANT]
> **数据搜集双负责人：武桐宇负责产业链、公司与产品映射数据；刘芯妤负责政策、公告、新闻和原始证据数据。** 两人从第一天同步开展，不需要互相等待。

### 吕洪宇｜队长：产品、总控与集成

1. 将比赛需求拆成 GitHub Issue，维护里程碑、优先级和每日站会记录；每项任务都写清验收标准。
2. 定义全项目统一 JSON：事件、图谱路径、公司候选、Wind 指标、证据引用和最终报告字段；提供可直接替换的 mock 数据。
3. 开发/组织总控 Agent：接收四个模块的 JSON，按“事件 → 图谱 → 公司 → 财务 → 证据 → 报告”组合结果，并记录每次调用过程。
4. 审查每个 PR 的数据来源、字段兼容性和可运行性；只把通过端到端演示的成果合入 `main`。
5. 制作答辩主叙事、演示脚本、风险说明和复现实验清单；每周选一个标准事件组织全链路验收。

**本周交付：** `schemas/` 字段规范、mock 端到端样例、总控流程图、可运行的演示主链路、答辩提纲。

### 武桐宇｜产业链数据与知识图谱

1. 建立节点字典：材料、电池、电机、电控、传感器、飞控、通信导航、无人机/eVTOL、起降场、低空服务场景等。
2. 为每个节点定义类型、同义词、上下游关系、来源链接和“待核验/已核验”状态。
3. 首批筛选 20–30 家相关上市公司，完成“公司—主营产品—产业环节—业务暴露度”的映射；不确定的映射必须标记待核验。
4. 编写至少 10 条事件传导规则，例如“碳纤维涨价 → 复材成本上升 → 整机毛利承压”，写明方向、适用条件和例外情形。
5. 输出 `nodes`、`relations`、`company_mapping`、`event_rules` 四份结构化文件，并用 3 个事件检查路径能否正确查询。

**本周交付：** 低空产业链 V1、20–30 家公司映射、10 条传导规则、3 条可展示的影响路径。

### 刘芯妤｜政策、公告、新闻与原始证据数据

1. 制定事件与证据字段：事件名称、类别、方向、发生日期、发布机构、原文标题、URL、原文摘录、适用地区、可信度和证据定位。
2. 优先收集政府部门政策、交易所/公司公告、适航或空域管理等一手资料；新闻只用于发现线索，结论必须回溯原始来源。
3. 建立至少 30 条可复核事件库，其中首批 10 条必须覆盖政策支持、适航进展、原材料价格、订单/合作、低空应用落地等类别。
4. 将长文切分为可引用证据片段，给每段分配 `evidence_id`，并标出它支持的结论，供 RAG 和前端证据抽屉直接读取。
5. 设计 30 个评测问题及标准答案要点：事件方向、应经过的产业节点、可能涉及的公司类别与必需证据。

**本周交付：** `events.csv`、`evidence.csv`、原文链接清单、首批 10 条核验完成案例、评测题 V1。

### 范笑薇｜Wind 数据、财务验证与量化评分

1. 输出 Wind 字段口径表：证券代码、报告期、营收、归母净利、毛利率、经营现金流、研发费用、存货、应收账款、估值、收益率等；说明单位、频率和缺失值规则。
2. 根据武桐宇提供的公司清单，先为 20 家样本公司导出近三年/近八季数据；**不上传受限原始 Wind 文件**，只上传字段说明、脱敏样例和可复现处理逻辑。
3. 清洗数据，统一证券代码、日期、币种/单位和异常值标记，生成可供总控调用的公司指标 JSON。
4. 实现可解释评分：`Impact = Exposure × Sensitivity × FinancialMateriality`；分别说明三个分项从何而来、如何归一化、权重为何这样设置。
5. 用 3 个典型事件做敏感性测试，输出公司排序、关键财务依据与“不足以判断”的边界情况。

**本周交付：** Wind 字段字典、20 家样本指标表、评分函数与测试、公司影响排名 JSON、方法说明。

### 孙奇衍｜前端、可视化与比赛 Demo

1. 不等待真实后端：先基于吕洪宇的 mock JSON 搭建事件输入、结果总览、产业链路径、公司排名和证据抽屉五个页面/区域。
2. 将武桐宇的节点/边渲染成可交互图谱：受影响路径高亮，节点点击后展示相关公司和规则说明。
3. 将范笑薇的评分结果展示为可排序公司卡片/榜单，明确利好、利空、不确定性和评分构成。
4. 将刘芯妤的 `evidence_id` 显示为可展开证据卡，包含标题、日期、摘录、来源链接和可信度，避免“无依据结论”。
5. 负责答辩现场可用性：加载状态、空数据提示、错误提示、截图/录屏素材和 3 分钟演示路径。

**本周交付：** 可点击前端原型、图谱高亮、公司评分榜、证据抽屉、演示截图/录屏脚本。

## 统一工作流

```text
事件 Agent ──────┐
图谱 Agent ──────┼──→ 总控 Agent ─→ 投研报告与过程追溯
财务 Agent ──────┤
证据 Agent ──────┘
```

四类分析可并行运行，不以单人完成为前置条件。总控 Agent 仅接收统一 JSON，不直接依赖内部实现。

## 周期性验收

- 每日 15 分钟站会：昨天交付、今日计划、接口阻碍；
- 每两天合并一次可运行小版本；
- 每周抽取一个标准事件做端到端演示；
- 所有结论必须有“原始来源 + 图谱路径/规则 + 计算结果”。
